## 收集方式

- 使用现有 Playwright 登录链路进入云端 jshERP。
- 只读取菜单、路由、列表、筛选项、表头、行操作和新增表单字段。
- 仅打开“新增”表单查看字段，没有点击保存、保存并审核、审核、反审核、删除、导入、导出、转单等会产生业务影响的按钮。
- 前端使用 history 路由，不能直接 `goto /bill/...`，需要在已登录的 SPA 内通过 Vue Router 切换路由，或通过左侧菜单进入页面。

## 已能由 AI 继续使用的资料

- 页面路由、菜单路径、列表筛选项、工具栏按钮、表头、行操作、新增表单字段已经足够支撑 Page Object 的第一版实现。

## 已确认的第一版 UI 写入策略

用户已确认第一版采购/销售 UI 链路采用以下策略：

1. 采购链路复用接口自动化基础数据：供应商 `自动化测试专用供应商`。
2. 销售链路复用接口自动化基础数据：客户 `自动化测试专用客户`。
3. 出入库复用接口自动化默认仓库：`自动化测试专属仓库3`。
4. 结算账户复用接口自动化单据账户：`自动化测试专用结算账户`。
5. 采购/销售固定商品使用 `请购单测试商品C`。
6. 当前链路点击 `保存（Ctrl+S）` 生成未审核采购/销售订单，再执行 `审核`，断言订单状态变为 `已审核`。
7. 订单审核后执行转单：采购订单转 `采购入库`，销售订单转 `销售出库`。
8. 转单弹窗中把目标单号改为 `AUTO_UI_PI_<ui_run_id>` / `AUTO_UI_SOUT_<ui_run_id>`，仓库选择 `自动化测试专属仓库3`，本次付款/本次收款填 `0`。
9. 转出的采购入库单/销售出库单只点击 `保存（Ctrl+S）`，断言状态为 `未审核`；不点击 `保存并审核`，不审核入库/出库单，不做付款/收款。
10. 单据编号使用 `AUTO_UI_PO_<ui_run_id>`、`AUTO_UI_PI_<ui_run_id>`、`AUTO_UI_SO_<ui_run_id>`、`AUTO_UI_SOUT_<ui_run_id>`，session teardown 只清理本轮 `AUTO_UI_` + `ui_run_id` 命中的单据数据。

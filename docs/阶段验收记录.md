### UI 后置测试数据清理机制（补充实现）

在 `ui/conftest.py` 中新增 session 级 `ui_run_id` 与 `ui_run_data_cleanup`：

- 触发时机：UI 测试 session 结束后执行一次（autouse session fixture teardown）；用例收集阶段不执行，不触发任何数据库操作。
- 运行 ID：`ui_run_id` 格式为 `YYYYMMDDHHMMSS`，本轮 UI 创建的单据编号约定为 `AUTO_UI_PO_<run_id>`、`AUTO_UI_PI_<run_id>`、`AUTO_UI_SO_<run_id>`、`AUTO_UI_SOUT_<run_id>`。
- 清理范围：只删除本轮创建的出入库单（`jsh_depot_head.number`）、收付款单（`jsh_account_head.bill_no`）及对应明细（`jsh_depot_item.header_id`、`jsh_account_item.bill_id/header_id`）。
- 双条件约束：所有清理 SQL 均同时满足 `AUTO_UI_` 前缀与本轮 `ui_run_id` 两个 LIKE 条件，并限定 `delete_flag = '0'`，不会命中历史数据。
- 清理顺序：先以子查询查出本轮单据 ID，先删收付款明细、出入库明细，再删收付款单、出入库单主表。
- 第一版 UI 不创建商品，不清理 `jsh_material`、`jsh_material_extend`、`jsh_material_current_stock`。
- 边界：不清理 `AUTO_API_*` 数据，不修改接口自动化清理逻辑；不删除供应商、客户、仓库、结算账户、固定商品等基础数据。
- 失败处理：每步清理失败会回滚并打印失败原因与失败项数量，不吞掉异常伪造成功；数据库配置缺失或连接失败时跳过并输出明确说明。
- 安全：控制台只输出 run_id、影响行数和失败原因，不输出数据库密码、Token、账号密码。
- 本机制未执行任何文件删除或目录清理。
